# 使用安排实施计划

> 此功能已移除。文档仅保留为历史设计记录，不代表当前应用行为。

目标：把当前额度和使用观察变成可查看的账号使用、休息和额度保留安排，同时将查询统计统一表述为次数。

本阶段提供使用建议，用户仍通过现有确认流程切换账号；不会自动暂停任务、使用重置卡或提前发送消息。

## 步骤

- [x] 统一次数文案，保留原始查询记录的数据格式。
- [x] 新增独立规划模块：5 分钟比较，账号额度用尽时按实际时间衔接，同时扣除 5h 与周额度，按实际首次使用启动待开始的窗口。
- [x] 优先寻找满足最长休息、最短连续使用和总休息上限的安排；找不到时显示当前找到的较好安排及超出的要求，不宣称数学上无解。
- [x] 提供工作起止时间、初始消耗速度、周额度换算和休息偏好。可按每日工作时间比例为周重置前的后续工作日保留额度。
- [x] 历史数据充足时单独给出速度对照，不按账号暗中改变当前设置的消耗速度；观察到的常用时段只参与同等方案的比较，不把没有观察到消耗的时间排除。
- [x] 接入独立页面与后台重算；显示总使用时间、最长休息、数据来源、每段结束后的额度保留目标。
- [x] 验证无账号、跨午夜、有限周额度、窗口启动、主动休息、过期查询和保留后续额度等场景，更新并检查 `dist/Codex Switch5.app`。

## 数据与边界

- 只使用最近 30 分钟查询到的额度；过期数据需要刷新，不从旧缓存推断已经恢复。
- 满额 5h 窗口按首次计划使用时开始计算，这是保守估计；已有部分消耗的窗口使用服务返回的重置时间。
- 未核实的未来重置属于预测，后续查询会修正。周额度按已有精确重置时间和七天周期预测。
- 每次查询间隔的平均消耗包含空闲，只作独立速度对照。所有账号采用统一的用户设置速度和周额度换算。
- 搜索保留有限数量的不同安排，结果是近似建议；没有找到满足条件的安排不代表不存在。
- 改动以新增模块为主，保留工作区已有修改，不删除记录，不生成 DMG。

## 验证与实现说明

- 定向检查通过：单账号分散休息、5h 与周额度约束、待开始窗口、跨午夜、过期查询、没有账号、后续工作日保留、重算扣除已消耗预算、总休息上限、连续使用和历史较快速度。
- 增加用户确认休息：保存固定结束时间，重算不得顺延。无法按时恢复时显示未满足要求，不把计划时长直接算成真实等待时长。
- 本次修正取消账号单独的当日预算上限，改为合并当前周剩余额度，按余下工作时间计算本次可用工作时长。旧预算记录不再参与计算。总休息上限明确针对余下的安排时段；过去的实际休息时长仍不能仅靠额度查询确定。
- 真实应用页面已显示下一步建议、总使用/休息时间、最长休息和每段额度目标；未改动现有账号切换执行流程。
- 本轮以新增规划模块、安排页面和定向检查为主；只更新应用，不生成 DMG，不删除原始查询记录。

- 最终应用已重启验证：使用习惯页面显示“查询次数”和“查询 N 次”；使用安排页面及展开的偏好设置正常显示。当前真实数据未找到满足全部偏好的方案时，界面显示明确提示。休息结束时间固定逻辑通过定向检查，未在真实使用中替用户启动休息。

## 本次修正

- 全体账号共享本次可用工作时长，不因单个账号日预算不足而浪费零散额度。
- 保留范围覆盖到最晚的当前周重置时刻，包括重置当天的工作时段；不预先计入较早重置账号的新周额度，因此偏保守，不是完整的多日最优分配。
- 搜索优先保留预计总可用时间，并比较实际累计使用与均匀分配进度的差距，避免提前耗尽后长时间等待。
- 即使未满足休息要求，也保留最短连续工作要求，候选方案不得伪装成已接受的偏好。
- 当前建议满足偏好、含后续工作且处于休息段时，沿用其结束时间；无可用数据时的全休息占位结果不固定结束时间；用户明确结束休息会清除旧建议再计算。
- 增加本机真实额度检查入口，验证连续工作长度、总使用时间与最长休息。

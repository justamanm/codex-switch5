目标：先积累可信的查询历史，显示观察到的消耗时间和速度，为后续使用规划提供依据。本阶段不接管自动切换，不推断实际等待时间。

实现方式：新增独立的本地追加记录文件；在应用的统一查询入口保存成功查询记录或失败事件，并保存切换事件。统计模块只比较同一账号、同一窗口的有效查询记录，界面显示记录覆盖情况与估计边界。

## 判定口径

1. 以服务查询记录的 `noted_at` 为观察时间，不以读取缓存时间代替查询时间。
2. 5h 与周额度分别比较各自的重置时间；任意额度回升或重置卡数量减少时，不用这一段估算消耗速度。
3. 查询失败打断该账号的连续观察；长间隔仍保留原始记录，但不据此精确定位消耗时段。
4. 保留无变化的成功查询；百分比取整造成的零变化不能证明没有工作。
5. 只显示观察间隔内的额度下降速度，不声称测出了实际工作速度；工作时段和等待偏好不自动覆盖用户设置。
6. 原始记录不自动删除；界面估计使用最近 28 天。精确工作时间、实际等待和自动规划属于后续阶段。

# 启动与用量刷新修复设计

## 目标

本次修改解决三个问题：

1. 启动首帧不再短暂显示“0 个账号”和“未识别”。
2. 自动刷新额度关闭时，Token 用量仍能以较低频率更新。
3. 凭证失效或重置卡详情查询失败时，不丢失已经取得的重置卡到期时间。

## 启动显示

`AppModel` 增加明确的首次载入状态。应用窗口可以立即出现，但账号数据尚未载入完成时，只显示居中的“正在载入本地账号…”。

本地账号、缓存额度和当前账号识别全部完成后，再一次性显示正常页面。网络额度刷新不属于首次载入：界面应先显示本地缓存，然后在后台更新额度，不能一直停留在载入状态。

首次载入失败时也必须结束载入状态，并在正常页面显示现有错误提示，不能永久显示进度指示。

## Token 用量更新

Token 统计仍采用增量扫描，只在本地读取 Codex 会话文件新增的完整记录，并将结果保存到 SQLite。

触发规则如下：

- 应用启动后立即扫描一次。
- 进入“用量统计”页时立即扫描一次。
- 手动刷新额度和切换账号后立即扫描。
- 开启自动刷新额度时，额度刷新完成后同步扫描，不额外创建 Token 定时任务。
- 关闭自动刷新额度时，每 5 分钟执行一次本地 Token 增量扫描，不发起网络额度请求。

自动刷新设置变化时必须取消旧任务并按新规则重新安排，避免同时存在两个计时任务。应用退出后任务随 `AppModel` 释放而结束。

## 重置卡到期时间

`account_usage.json` 继续保存每个账号当前状态，包括重置卡数量和每张卡的到期时间。

刷新规则如下：

- 重置卡详情接口成功时，以接口返回的数量和到期时间更新已保存值。
- 用量接口明确返回 0 张卡时，清空已保存的到期时间。
- 用量接口仍显示有卡，但详情接口失败时，保留上次已知到期时间；新增但无法确认的卡继续显示“到期时间未知”。
- 凭证失效时保留最后一次成功保存的数量和到期时间。
- 凭证重新有效且详情接口成功后，再用新结果更新。

`QuotaObservation` 同步保存重置卡到期时间，使 SQLite 额度历史能够在当前缓存缺失时恢复最后一次成功结果。

## 错误边界

- 本地 Token 扫描失败只显示统计错误，不触发额度查询，也不清空已保存的统计。
- 重置卡详情是补充信息；详情接口失败不能让整个额度刷新失败。
- 凭证失效时继续保留最后一次有效额度和重置卡信息，并提示重新登录。
- 只有已确认的新数据可以覆盖已保存的重置卡到期时间。

## 验证

核心检查需要覆盖：

- 首次载入状态开始、成功和失败都能正确结束。
- 自动刷新开启时不启动独立 Token 计时任务。
- 自动刷新关闭时使用固定 5 分钟间隔。
- 详情接口失败保留已保存的到期时间。
- 明确 0 张卡时清空到期时间。
- 详情接口恢复后替换为新到期时间。
- 凭证失效及从 SQLite 恢复时保留到期时间。

完成核心检查后重新生成正式应用，并验证签名和 SQLite 链接。

# 不可查询账号暂停自动刷新设计

## 问题

部分账号的额度接口会持续返回不会自行恢复的错误，例如 HTTP 402。现有程序只会跳过已经标记为登录失效的账号，因此这些账号仍会进入每一轮自动刷新，反复发起无效查询。

## 方案

- 登录令牌失效或凭据内容不完整时，继续标记为“需要重新登录”。
- HTTP 402 等不会自行恢复的客户端错误，以及无法识别的额度响应，标记为“自动查询已暂停”。
- 网络中断、HTTP 429 和服务端错误仍按现有规则有限重试，并允许下一轮自动刷新再次查询。
- 自动刷新跳过“需要重新登录”和“自动查询已暂停”的账号。
- 单账号手动刷新不受暂停限制；查询成功后自动解除暂停。
- 暂停期间保留最后一次成功取得的额度和重置时间，并明确标为历史数据。
- 暂停账号不参与推荐备用账号计算，也不触发额度重置后的自动查询。

## 数据

在现有账号额度记录中增加两个可选字段：自动刷新是否暂停、暂停原因。缺少这些字段时按“未暂停”读取，不需要迁移数据库或凭据文件。

## 验证

- HTTP 402 首次出现时保存暂停状态，并向界面报告本次失败。
- 后续自动刷新跳过该账号，不再发起请求。
- 手动刷新仍可重新尝试；成功后清除暂停状态。
- 临时网络错误、HTTP 429 和服务端错误不会被永久暂停。

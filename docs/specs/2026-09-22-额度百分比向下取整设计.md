# 额度百分比向下取整设计

## 问题

ChatGPT 显示 5 小时剩余额度为 0% 时，Codex Switch5 可能显示 1%。原因是接口返回小数形式的 `used_percent`，程序将 `100 - used_percent` 四舍五入为整数。实际剩余不足 1% 时，四舍五入会高估可用额度。

## 方案对比

1. **向下取整（采用）**：所有小数剩余额度统一向下取整，不高估可用额度，规则简单一致。
2. **只对不足 1% 的值特判**：能修复当前现象，但引入了不必要的特殊规则。
3. **继续四舍五入**：保持现状，但会继续在边界值上高估额度。

## 实现

- 在核心模块增加可单独检查的剩余百分比换算函数。
- 先计算 `100 - used_percent`，再向下取整，最后限制在 0～100。
- 5 小时额度和周额度共用同一规则。
- 不改动已保存的历史记录；下一次额度刷新后使用新值。

## 检查

- `used_percent = 0` 时剩余 100%。
- `used_percent = 0.1` 时剩余 99%。
- `used_percent = 99` 时剩余 1%。
- `used_percent = 99.1` 和 `99.9` 时剩余 0%。
- `used_percent = 100` 时剩余 0%。
- 超出正常范围的值仍被限制在 0～100，避免界面异常。

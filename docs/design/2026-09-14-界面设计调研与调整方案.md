# Codex Switch5 界面设计调研与调整方案

日期：2026-09-14。阶段：研究与方案，尚未修改应用代码。

## 结论

推荐做成温和、清晰的原生 Mac 工具：暖白和深灰构成主体，少量蓝色突出操作，依靠对齐、间距和文字层次组织信息。保留账号列表、快捷切换和全部现有功能。

“随和”不是加可爱插画，而是用户打开后能看懂现状，知道下一步，遇到问题时不慌。当前最需要解决的是信息挤在一行、强调过多、旧数据与有效数据区别不足。

## 调研依据与边界

- 已查看实际运行的账号页、Token 统计页、切换记录页，以及使用习惯的界面文字；结束后恢复账号页及原统计子页选项。
- 已核对 README、DashboardView.swift、ContentView.swift 和使用习惯页面结构。README 截图早于当前界面，不能直接当作现状。
- 没有刷新、切换、新增、移除账号，也没有读取认证文件。设置、登录和确认弹窗的建议来自代码，未实际执行业务流程。
- 以下获奖和编辑推荐是可核查的认可证据，不等于当前下载量、市场份额或满意度。对“为什么好用”的解释属于结合产品展示和官方访谈的设计分析，不声称已做用户研究。

## 提炼出的原则

1. 先回答用户的问题，再展示内部数据。首页先回答“现在用谁、还剩多少、可以切到谁”。
2. 简约来自组织。常用功能直接可见；低频操作放在明确标注的菜单中，不能只靠悬停或右键发现。
3. 同类信息在同一位置。额度值对齐，重置时间放在各自额度下方，避免一长串字段。
4. 颜色只承担少量明确工作。按钮的蓝色表示可操作；状态同时用文字表示，避免靠绿色名字识别当前账号。
5. 让人放心的反馈比装饰更重要。刷新失败时保留旧值并标明；取消是正常结束；成功提示简短。
6. Apple 的材料效果服务于导航和操作层。数字和长文本不适合大面积透明背景，旧系统也应清晰可用。

## 当前问题与调整

| 当前观察 | 对使用的影响 | 调整方案 |
| --- | --- | --- |
| 实际窗口约 1006 像素宽，重置时间紧贴下一列，右侧卡片图标、刷新、分组、更多、切换拥挤 | 比较额度时视线被打断；部分内容难读 | 改成两行账号记录，额度与时间上下排列，统一列宽 |
| 当前账号和推荐账号分别用绿、蓝名称，并配人物、叶子和中央箭头 | 颜色和图形需要学习含义 | 以“正在使用”“推荐备用”文字为主；切换按钮放在目标名称旁 |
| 顶部和列表重复账号数 | 重复内容占据空间 | 数量只保留在列表标题旁；更新时间放列表附近 |
| 几乎每行都是独立圆角白卡，背景、描边、颜色共同强调 | 页面像控件拼装而非连续列表 | 分组使用共同实底与细分隔；当前账号只保留轻底色和文字标记 |
| 登录失效行仍突出显示历史的 100% | 容易把旧额度理解成当前可用额度 | 旧值保留但注明“上次记录”；“需要重新登录”比历史数值更醒目 |
| 统计中总 Token、金额、输入、缓存、输出、推理同时突出 | 首屏没有明确阅读顺序 | 总量为第一层，金额标为“API 等值估算”，分项第二层，详细规则折叠 |
| 切换记录重复完整日期、成功图标和成功文字 | 重复信息多 | 按日期分组，行内显示时间、来源、目标、结果；保留完整时间与失败详情入口 |

当前实现已经有页面分区、更多菜单、取消反馈和系统弹窗，无需全部推翻。尤其不要把已有明确提示删成一枚不知含义的图标。

## 布局选择

| 方向 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| A：顶部三项导航＋安静的账号列表 | 保持使用习惯，为两种额度保留最大宽度 | 不适合未来大量一级页面 | 推荐当前阶段采用 |
| B：左侧导航＋右侧列表 | 页面较多时容易定位 | 当前只有三项页面，窄窗口更挤 | 暂不采用 |
| C：一账号一张大卡片 | 单账号展示漂亮 | 多账号比较和拖动排序变慢，滚动增加 | 不适合核心任务 |

## 推荐页面方案

### 账号页

- 顶部：应用名称适度显示，账号／用量统计／切换记录居中，刷新与添加账号在右侧，设置保留标准入口。
- 摘要：左边“正在使用＋账号名＋两种剩余额度”，右边“推荐备用＋账号名＋两种剩余额度＋切换到此账号”。去掉中央悬浮箭头和与账号无关的叶子隐喻。
- 列表工具：标题“账号 · 9”，排序按钮显示已启用规则数；分组菜单内保留按组显示、管理分组，不能取消功能。
- 一行账号使用两层：第一层为名称、剩余 5 小时额度、剩余周额度和切换操作；第二层为身份补充、各自重置时间和重置卡数量。
- 单账号刷新和更多入口保持可见，但使用轻量按钮。换组、别名和移除集中于更多菜单；希望保持高频换组时，可直接点击组名进入同一菜单。
- 拖动把手持续可发现；自动排序期间的提示和手动排序恢复沿用现有规则，不改变排序行为。
- 当前账号的“使用”禁用按钮改成清楚的“正在使用”状态文字。
- 失效账号突出重新登录，历史额度注明上次记录；现有切换入口及规则仍保留，不能在视觉改版中暗自删除。

### 用量统计页

- 一级导航可显示“用量统计”，页内仍说明是 Token，保留统计信息／账号明细／使用习惯。
- 今日、本周、本月总量保持同时可比较。各项输入、缓存、输出、推理及自动审查仍可查看，使用较轻字体和统一列对齐；不改变计算方式及字段关系。
- 金额默认可用简短值便于扫读，但点击或展开必须可查看原精度；标明 API 等值估算，不暗示实际订阅账单。
- 历史图表保留每日／每周／每月。坐标标题明确单位，金额详情可点击查看，不能仅在悬停中出现。
- 使用习惯把图表、统计范围和实际覆盖日期放前面，观察记录数量其次；详细计算规则放“这些数据如何计算”。本机记录限制和数据不足状态仍常驻。
- 不把采样时间当作实际工作时间，不新增“还能工作多久”之类没有证据的结论。

### 切换记录页

- 保留账号切换／分组切换，日期作为分组标题。
- 每条保持来源、目标、结果和时间，失败展开原始原因；不改保存数量和记录内容。
- 成功使用中性文字与小勾，失败使用清楚的文字和适度警示色。

### 设置与任务弹窗

- 设置按现有内容分为自动刷新、语言等清楚小节，解释紧贴对应选项。
- 登录过程使用明确步骤和当前进度；终端命令仅在确实需要 CLI 登录时呈现。
- 切换前继续说明现有的 CLI 退出和应用重开要求，保持原确认流程。
- 错误先用一句话解释“发生了什么、目前结果”，再展开技术细节；不能在状态尚未确认时承诺已恢复。
- “已取消添加账号”作为短暂正常提示，真正恢复失败才提示需要处理。
- 移除继续使用现有移到废纸篓机制和确认，不为追求干净界面省略恢复说明。

## 视觉规格初稿

以下数值是实施起点，不是 Apple 官方强制标准，需以实际原生渲染校准。

| 项目 | 建议 |
| --- | --- |
| 浅色背景 | 暖灰白 #F5F5F2，内容底 #FFFFFF |
| 文字 | 主文字 #242629，次要文字 #63676D |
| 主操作 | 克制的蓝 #3869AD；可比较石墨灰方案 |
| 颜色规则 | 绿色只作成功补充，橙色提示需关注，红色用于失败和危险操作；全部附文字 |
| 字体 | 系统字体；正文约 13–14 pt，区块标题 16–18 pt，核心额度 16–20 pt；减少到处加粗 |
| 间距 | 内容边距约 20–24 pt；组间约 20 pt；列间至少 16 pt |
| 行高 | 两行记录约 68–76 pt；拥挤时换行而非缩小关键文字 |
| 圆角 | 内容容器约 10–12 pt；按钮尽量采用系统形态；避免每个字段套胶囊 |
| 深色 | 使用独立语义颜色；背景深灰、文字浅灰，重新检查次要文字和按钮对比度 |
| 动画 | 约 120–180 ms，仅用于说明变化；尊重减少动态效果设置 |

不要把 ContentView 全局 large 控件和强制 xxLarge 当成无障碍方案。应按控件用途设置尺寸，并检查系统文字设置、键盘焦点和 VoiceOver 名称。普通文本对比度以至少 4.5:1 为验收目标，关键非文本状态至少 3:1；具体配色还需实测。

## 图标与界面关系

用户提供的图标是暖白圆角底、石墨色循环箭头、5h 字样，适合中性的界面。图标可保留微立体感，按钮和数据保持平实，两者不冲突。

需要检查的三个问题：

1. 小尺寸下 h 和箭头渐隐部分可能不够清楚；应分别检查 16、32、64、128 像素原生尺寸。
2. 两个循环箭头更容易让人想到刷新或重置，而产品主要是切换账号；可以保留品牌，但需用应用名称与文案补足含义。
3. 当前图片包含图标外白底和投影，不宜把整张图直接当最终图标资源；正式制作需要适配系统图标模板，避免双重边框和缩得过小。

先确定界面方案，再微调箭头粗细、5 与 h 的比例和暗色版本。无需强制把图标染成蓝色，也无需因旧界面是绿色而继续大面积使用绿色。本轮不编辑图标。

## 实施顺序与验收

第一步解决两行账号布局和时间拥挤，再统一字体与颜色；第二步调整摘要与管理菜单；第三步整理统计、记录与弹窗。每一步都核对功能保留表。

本轮只新增研究文档和独立示意，不改应用源码，不构建或提交。后续预计主要改动 DashboardView.swift、UsageLearningView.swift、ContentView.swift 和 Localization.swift；以替换与整理现有显示代码为主，不修改 Core 的登录、额度、推荐、排序和统计算法。尚未写代码，不能可靠估计增删行数。完成实现时应报告实际新增／删除行数，避免再叠一套并存界面。

验收场景：

- 760、1000、1440 宽度，长账号名、中英文、深浅色；不得字段重叠，窄窗口允许账号行重新排布。
- 零账号、单账号、多分组、30 个账号；首屏能找到当前账号与推荐入口。
- 数据为 0%、100%、未知、过期、查询失败、登录失效；未知不能显示为零，旧值不能假装实时。
- 不改变刷新后的顺序规则；操作中不意外移动正在点击的目标；拖动仍保持现有含义。
- 键盘可以到达全部操作，图标按钮有名称，颜色不是唯一状态提示。
- 首次接触者应能在约 5 秒内回答“当前用谁、还剩多少、点哪里切换”；此为待验证目标，不是已通过结果。
- 视觉示意仅用于评审布局，不代表已实现全部交互或通过原生界面测试。
